Task 2. Preprocessing Pipeline
Build a clean, reusable preprocessing pipeline. All logic should live in src/preprocessing.
py as functions or a class, so it can be imported and reapplied in future assignments without modification.
Order matters – split first, preprocess second. A common and serious mistake
is to compute imputation statistics (e.g. the median for missing value treatment) or
outlier boundaries (e.g. IQR bounds) on the full dataset before splitting. This is
data leakage: information from the validation and test sets silently influences your
preprocessing. The correct workflow is: (1) split the data, then (2) compute all
statistics on the training set only, then (3) apply them to all three sets.
The subsections below follow this order exactly.

2.1. Train / Validation / Test Split
The very first step in your pipeline – before any imputation, outlier treatment, encoding,
or scaling – is to split your dataset into three non-overlapping partitions.
• Training set (80%): used to fit all preprocessing steps and both models.
• Validation set (10%): used during model training to monitor overfitting and guide
early stopping. It also serves as a final confirmation of model selection before the test
set is ever touched.
• Test set (10%): used once at the very end to report final performance. Never use it
during training or tuning.
The standard approach is to perform this in two sequential splits: first hold out 10% as
the test set, then from the remaining 90% hold out approximately 11%, which yields the
80/10/10 proportion overall.
For classification problems, use stratified splitting to preserve the class ratio across all
three partitions. For time series data, do not shuffle – split chronologically instead.
Example:
The e-commerce dataset (10,000 rows) is split 80/10/10. Because returned is imbalanced (85% not returned, 15% returned), stratify=y is used in both split steps to
preserve the class ratio. Final shapes: Train (8,000 rows), Validation (1,000 rows),
Test (1,000 rows). All subsequent preprocessing statistics are computed exclusively
on the 8,000 training rows.
2.2. Missing Value Treatment
Detect and handle missing values in each column. All imputation statistics (medians,
modes, fill values) must be computed on the training set only and then applied
identically to the validation and test sets.
Common strategies:
• Numerical columns: impute with mean or median (prefer median for skewed distributions).
• Categorical columns: impute with the mode or a dedicated "Unknown" category.
• Target column: drop rows where the target is missing.
Example:
In the training set, price has 3% missing values. Because price is right-skewed,
the median of X_train["price"] is computed and used for imputation. This same
median value is then used to fill missing entries in X_val and X_test – their own
medians are never computed separately. product_category missing values are filled
with "Unknown" across all three sets.

Apply at least one method to detect and handle outliers in numerical features. All boundary values must be computed on the training set only and then applied to all three

Two standard approaches:
• IQR method: flag values below Q1 − 1.5 · IQR or above Q3 + 1.5 · IQR.
• Z-score method: flag values with |z| > 3.
Once detected, you may either remove the outlying rows or cap (Winsorize) the values
at the boundary – justify your choice.
Example:
The IQR upper bound for price is calculated on X_train as $450. Values above
$450 in X_train, X_val, and X_test are all capped at $450 (Winsorizing). The $450
bound is never recalculated on the validation or test sets.
2.4. Encoding Categorical Variables
Convert categorical columns into numerical form. Choose the encoding method based on
the nature of each variable:
• One-Hot Encoding: for nominal categories with no inherent order (e.g. region,
product_category).
• Label Encoding: for binary columns or ordinal categories (e.g. is_member).
• Target Encoding: for high-cardinality categorical columns where one-hot would
produce too many features.
Example:
product_category (5 unique values) is one-hot encoded, producing 4 binary columns
(drop_first=True to avoid multicollinearity). region (4 values) is also one-hot encoded. is_member is already binary (0/1) and requires no transformation.
2.5. Feature Engineering
Create at least 2 new features derived from existing columns. New features should
encode domain knowledge that the model cannot easily learn from raw inputs. These
features are added to the dataset alongside the original columns – they do not replace
them. Your dataset will therefore have more than 8 columns after this step, which is
expected.
Example:
Feature 1 – revenue = price × quantity × (1 − discount_pct/100): captures the
actual monetary value of the transaction, more predictive of return behaviour than
price or quantity alone.
Feature 2 – engagement_score = 1/(days_since_last_purchase+1): captures customer recency in a bounded, non-linear form. A customer who purchased yesterday
scores near 1; one who last purchased 365 days ago scores near 0.
Both features are added as new columns. The original price, quantity, discount_pct,
and days_since_last_purchase columns remain in the dataset.

2.6. Feature Scaling
Apply scaling to numerical features so that no single feature dominates due to its range.
The scaler must be fitted on the training set only, then applied to all three sets. Save
the fitted scaler object – you will need it in Homework 2.
• StandardScaler: transforms to zero mean and unit variance. Preferred for linear
models and neural networks.
• MinMaxScaler: scales to a [0, 1] range. Preferred when the distribution is bounded
or uniform.
• RobustScaler: uses median and IQR instead of mean and std. Preferred when
outliers remain after treatment.
Example:
StandardScaler is fitted on X_train and then used to transform customer_age,
price, quantity, days_since_last_purchase, revenue, and engagement_score
across all three splits. The fitted scaler is saved as models/scaler.pkl.
2.7. Exploratory PCA (Dimensionality Insight)
After scaling, run a Principal Component Analysis (PCA) on the training feature set
as a mandatory exploratory step. The goal here is not to reduce dimensions for modelling
– it is to understand which features carry the most information and how much variance
each principal component explains.
Why PCA must come after scaling: PCA directions are determined purely
by variance. On unscaled data, features with large numerical ranges (e.g. revenue
in the thousands) will dominate all principal components regardless of their true
informativeness. Always run PCA on scaled data.
Specifically, you should:
• Plot the explained variance ratio per component (scree plot) to see how many
components are needed to capture, say, 90% of the total variance.
• Inspect the PCA loadings (component weights) to identify which original features
contribute most to the first two or three principal components.
• Produce a 2D scatter plot of your data projected onto the first two principal components, coloured by target class.
The insights from this step should be discussed in your README.
Example:
PCA is run on the scaled X_train (10 features post-engineering). The scree plot shows
that the first 3 components explain 74% of total variance and the first 5 explain 91%.
Inspecting the loadings reveals that revenue, price, and engagement_score dominate the first principal component, confirming that transaction value and customer
recency are the most informative axes of variation. The 2D scatter plot shows a rough
separation between returned and non-returned transactions along PC1.

3.2. Neural Network
Train a feedforward neural network on the same preprocessed data. Keep the architecture
simple and focused – the goal is a fair comparison, not an exhaustively tuned deep learning
system.
Architecture requirements:
• At least 2 hidden layers
• Use ReLU as your default activation function in hidden layers. You are encouraged to
experiment with at least one alternative (e.g. Leaky ReLU, ELU, Tanh) and report in
your README how the choice affected training behaviour and validation performance
• Appropriate output activation for your problem: Sigmoid for binary classification,
Softmax for multi-class, linear (no activation) for regression
• Dropout (e.g. 0.2–0.3) on at least one hidden layer for regularisation
Training requirements:
• Use the validation set (X_val / y_val) to monitor validation loss at each epoch
• Implement early stopping: halt training when validation loss has not improved for
a set number of epochs (patience), and restore the weights from the best epoch
• Plot the training and validation loss curves across epochs
You may use either PyTorch or Keras/TensorFlow although PyTorch is recommended. Save the trained model as models/neural_network.pt (PyTorch) or
models/neural_network.h5 (Keras).
Example:
Architecture – Input(10) → Dense(64, ReLU) → Dropout(0.3) → Dense(32, ReLU)

Training – Adam optimizer, binary cross-entropy loss, batch size 64, early stopping
